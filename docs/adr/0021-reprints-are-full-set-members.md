# Reprints join a set's pool as full members, declared by a generated 0set.go

## Context

ADR 0017 wired the legacy pool: it made **one `deckgen.Set` per source set**,
keyed each card to its first provenance `Ref`, gave every set only its own cards
as pool members, and folded every _other_ set's cards into that set's legacy
pool. Under that model a card belonged to exactly one set's pool — the set that
introduced it — and reached any other set only as a rare same-House legacy draw.

KeyForge sets do not work that way. A later set is roughly half **reprints** —
cards that first appeared in an earlier set and are printed again as ordinary
members of the new one. Age of Ascension shares ~50% of its cards with Call of
the Archons; those cards are as much a part of an AoA deck as AoA's own new
cards, not rare legacy guests. ADR 0017 modeled every AoA appearance of a CotA
card as legacy, which under-weights it enormously.

Two facts had to be reconciled. A card is implemented **once**, in the package of
the set that introduced it (its _native_ set) — re-implementing it in every set
that reprints it would duplicate behavior and desync. But a reprint must count as
a full pool member of every set that prints it. And a set package must not import
another set package (the dependency arrow points one way: `cards → card →
deckgen → engine`, ADR 0003).

## Decision

A set's provenance catalog is the canonical list of the cards **in** that set.
`mage tool:stub <slug>` reads it and generates, alongside the per-card stubs, a
`0set.go` in the set's package that catalogs the set's **reprints** — the cards
in its catalog that are implemented in a _different_ set — as `card.Reprint`
calls in `init()`:

```go
// Code generated by "mage tool:stub ageofascension"; DO NOT EDIT.
package ageofascension

func init() {
    card.Reprint(card.AoA, 359, "Mighty Tiger")
    // ... every AoA card implemented in an earlier set, by collector number ...
}
```

`card.Reprint(set, number, name)` records a `ReprintRef` in a package-level list
that the `cards` aggregator reads through `card.ReprintRefs()`. A reprint is
declared **by name**, not by importing the implementing package, so the one-way
dependency holds. `DeckSets()` resolves each claim to the registered card of that
name (`reprintsBySet`) and folds it into the set's own pool (`ownPool`): a set's
pool is now its natively implemented cards **plus** its reprints, each a full
member the same as a new card. A reprint whose name a native card already fills is
pooled once.

Legacy is unchanged. A set still carries every _other_ set's cards as its legacy
pool. So a card native to CotA and reprinted in AoA is in AoA's own pool (as a
reprint) **and** in AoA's legacy pool (as a CotA-native card). A legacy draw in an
AoA deck may therefore land on a card AoA already reprints — which is correct: a
legacy pull is "a card from another set," and that card is sometimes one this set
also prints.

## Consequences

- A set's membership is derived from its provenance catalog, exactly as
  `CONTEXT.md` says (a **Set** is what the card database groups, a **Reprint** is a
  card that appears in a set other than its native set, and a card may belong to
  several sets at once). The catalog is the source of truth; `0set.go` is its
  generated projection into Go.
- A reprint is implemented once, in its native set, and claimed — never
  re-implemented — everywhere it is reprinted. `TestNoDuplicateImplementations`
  keeps a second real implementation from sneaking in; a stale duplicate (the old
  hand-written AoA Mighty Tiger) is deleted, and the reprint claim replaces it.
- Regenerating a set is idempotent: `mage tool:stub <slug>` rewrites `0set.go`
  from the catalog, adding the header `DO NOT EDIT`. A set with no reprints gets no
  `0set.go` (any stale one is removed).
- This extends ADR 0017 rather than replacing it: the per-source-set `deckgen.Set`
  and the legacy pool stay; what changes is that a set's pool now includes its
  reprints, so later sets are full pools in their own right instead of thin sets
  that lean entirely on legacy draws. `DeckSet()` still defaults to the first
  released set for callers that want one guaranteed-full pool.
